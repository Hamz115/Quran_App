# Session Log: Fix 11 Bugs + Dashboard Improvements (v1.7.0)

**Date:** 2026-03-07
**Session:** 001

## Objective

Fix 7 bugs reported after testing with demo accounts: 3 Tauri bugs (class creation, student pre-select, stale data) and 4 Flutter bugs (wrong password splash, stale data, empty classes, invalid date). Bump version to v1.6.8.

## Summary

Fixed 7 bugs across Tauri and Flutter platforms, plus 2 additional issues found during testing. Tauri fixes include using React Router navigate() instead of window.location.href for class creation, passing student IDs in URL for pre-selection, and clearing cache on logout. Flutter fixes include not setting global isLoading during signIn/signUp, adding ValueKey on MainNavigation for fresh state on login, defensive date parsing, clearing local SQLite on user switch, and invalidating all providers after sync pull.

### Flutter Fix #8 (found during testing): Local SQLite data leakage between users
- **Root cause**: `getStats()` counts ALL classes in SQLite with no `teacher_id` filter. On user switch, old user's classes remain in SQLite, inflating stats for the new user.
- **Fix**: Call `classRepo.clearAllLocal()` and `mistakeRepo.clearAllLocal()` at the start of `_initLocalFirst()` to wipe stale SQLite data before pulling fresh data from Supabase.
- Files modified: `quran_mobile/lib/main.dart`

### Flutter Fix #9 (found during testing): Stats not updating after Supabase sync
- **Root cause**: After `pullAll()` downloads fresh data, only `classesProvider` and `mistakesProvider` were re-invalidated. `statsProvider`, `topMistakesProvider`, `mistakeCountsBySurahProvider`, and `enrolledClassesProvider` kept stale values, causing "Total Classes" to not update until manual refresh.
- **Fix**: Invalidate ALL data providers after `pullAll()`, not just classes and mistakes.
- Files modified: `quran_mobile/lib/main.dart`

### Flutter Fix #10 (found during testing): Teacher dashboard stats slow to load
- **Root cause**: "Total Classes" and "Classes This Week" stats went through SQLite round-trip (clear → pullAll → read), while "Total Students" queried Supabase directly (instant).
- **Fix**: Created `teacherClassDatesProvider` that queries Supabase directly (like `teacherStudentsProvider`). Dashboard now derives both teacher class stats from this provider — all 3 teacher stat cards load instantly.
- Files modified: `quran_mobile/lib/presentation/providers/providers.dart`, `quran_mobile/lib/presentation/screens/dashboard/dashboard_screen.dart`

### Flutter Fix #11 (found during testing): Raw exception shown for wrong password
- **Root cause**: `LoginScreen._handleLogin()` catch block used `e.toString()` which dumps the full `AuthApiException(message:..., statusCode:..., code:...)` string instead of a clean message.
- **Fix**: Added `AuthApiException` type check to extract just `e.message` ("Invalid login credentials").
- Files modified: `quran_mobile/lib/presentation/screens/auth/login_screen.dart`

### Flutter Enhancement: Recent Classes with student names + max 3 on mobile
- Created `classStudentNamesProvider` (Supabase-direct) — fetches class→student name map in one query
- Dashboard Recent Classes now shows student names next to the day name
- Limited to 3 recent classes on mobile (was 5) for bigger, more readable cards
- Files modified: `quran_mobile/lib/presentation/providers/providers.dart`, `quran_mobile/lib/presentation/screens/dashboard/dashboard_screen.dart`

### Critical Fix: Classes invisible to students (is_published missing)
- **Root cause**: Flutter `_backgroundPushClass()` was missing `is_published: true` when inserting classes to Supabase. Web correctly sets this field. Since the web student query filters by `is_published = true`, Flutter-created classes were invisible to students on BOTH Tauri and Flutter.
- **Fix 1**: Added `'is_published': true` to Flutter's Supabase class insert
- **Fix 2**: Added one-time auto-fix in both Flutter (`_fixUnpublishedClasses`) and Tauri (`supabase-api.ts`) that patches any existing unpublished classes when a teacher loads their classes
- Files modified: `quran_mobile/lib/presentation/providers/providers.dart`, `quran_frontend/src/lib/supabase-api.ts`

## Issues Encountered

- **Fix #5+6 insufficient**: Initial provider invalidation + ValueKey fix wasn't enough — local SQLite still held the previous user's data. `getStats()` counts all classes without filtering by `teacher_id`, so stale SQLite rows leaked into the new user's dashboard. Fixed by clearing SQLite before pulling new data.
- **Staggered provider updates**: After `pullAll()`, only 2 of 7 providers were re-invalidated, causing stats to load in stages (students → classes this week → total classes never). Fixed by invalidating all providers after pull.
